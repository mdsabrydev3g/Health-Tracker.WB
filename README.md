# Health Tracker

تطبيق عائلي شخصي لمتابعة الأدوية والصحة — **ليس جهازاً طبياً**، ولا يقدّم أي استشارة أو تشخيص طبي.

الهدف بجملة واحدة: **ألا تفوت الوالدة جرعة قلب أبداً، وألا يضطر مسؤول الرعاية للتساؤل عمّا إذا كانت أخذتها.**

---

## المستخدمان

| المستخدم | الجهاز | ما يراه |
|---|---|---|
| **الوالدة** (مريضة قلب، ~٩ أدوية) | أندرويد ١٥/١٦ | شاشة واحدة: الجرعة القادمة + زر كبير «أخذت الدواء» + تأجيل |
| **مسؤول الرعاية** (ابنها/ابنتها) | أندرويد + ويب/ويندوز | كل شيء: اليوم، الأدوية، المخزون، التقارير |

---

## التقنيات

| الطبقة | المستخدم |
|---|---|
| الإطار | **Next.js 16** (App Router) + TypeScript + React 19 |
| الواجهة | Tailwind CSS + مكونات RTL عربية (حد أدنى للّمس ٤٨dp) |
| قاعدة البيانات | **Neon Postgres** + Drizzle ORM |
| المصادقة | حساب واحد لمسؤول الرعاية — جلسة JWT في كوكي `httpOnly` |
| الاستضافة | **Vercel** |
| الجوال | Capacitor (أندرويد، targetSdk 35) + PWA قابلة للتثبيت |

### تغيير مقصود عن الخطة الأصلية

الخطة الأصلية كانت تعتمد **Firebase** (Auth / Firestore / Cloud Functions / FCM). بناءً على طلبك انتقلنا إلى **Neon + Vercel**، وترتب على ذلك:

| بدلاً من | نستخدم | ملاحظة |
|---|---|---|
| Firebase Auth | JWT + `httpOnly` cookie | حساب واحد فقط، فلا حاجة لمزوّد خارجي |
| Firestore | Neon Postgres | نفس نموذج البيانات ١:١ |
| Cloud Functions | Vercel Functions / Server Actions | مفاتيح الذكاء الاصطناعي تبقى جهة الخادم |
| FCM | إشعارات محلية (Capacitor) + Web Push | مسار التذكير يبقى محلياً وهو الأهم |

## التشغيل محلياً

```bash
cp .env.example .env.local     # ثم املأ القيم
npm install
npm run db:generate            # توليد migration (اختياري، موجود مسبقاً)
npm run db:migrate             # تطبيق المخطط على قاعدة البيانات
npm run db:seed                # حساب مسؤول الرعاية + الوالدة + ٩ أدوية
npm run dev                    # http://localhost:3000
```

بيانات الدخول الافتراضية بعد `db:seed`:

```
caregiver@example.com / change-me-now     (رقم المرور: 1234)
```

> **غيّر كلمة المرور ورقم المرور فوراً بعد أول دخول.** هذه قيم تجريبية.

### إعداد Neon

1. أنشئ مشروعاً في [Neon](https://neon.tech).
2. من Connection details انسخ **Pooled connection** وضعه في `DATABASE_URL`.
3. لعمل `drizzle-kit` استخدم الرابط المباشر (غير المجمّع) في `DATABASE_URL_UNPOOLED`.
4. شغّل `npm run db:migrate`.

> ملاحظة: `drizzle-kit` يستخدم مشغّل Neon الذي لا يتصل بقاعدة محلية عبر WebSocket. للاختبار المحلي على Postgres عادي، طُبّق المخطط مباشرة أو استخدم `psql`.

## النشر على Vercel

1. اربط المستودع بمشروع Vercel (يُكتشف تلقائياً كـ Next.js).
2. أضف متغيرات البيئة: `DATABASE_URL`، `AUTH_SECRET`، `NEXT_PUBLIC_SITE_URL`.
   ```bash
   openssl rand -base64 48     # لتوليد AUTH_SECRET
   ```
3. `npm run db:migrate` مرة واحدة مقابل قاعدة الإنتاج.
4. Deploy. ملف `vercel.json` يضيف ترويسات أمان أساسية.

## تطبيق الجوال (أندرويد)

النسخة الحالية **قابلة للتثبيت كـ PWA** فوراً (ملف `manifest` مضمّن). ومشروع أندرويد الأصلي **مولّد مسبقاً** في `android/`:

```bash
npm run cap:sync           # يبني الويب وينسخه إلى android/
npx cap open android       # يتطلب Android Studio لتجميع APK/AAB
```

الإعدادات جاهزة في `android/variables.gradle`:

```gradle
minSdkVersion = 26          // أندرويد 8+
targetSdkVersion = 35       // أندرويد 15
compileSdkVersion = 36
```

**بلوجن Java مخصص** في `android/app/src/main/java/com/healthtracker/app/AlarmHealthPlugin.java`
يسجّل في `MainActivity` ويفحص: `canScheduleExactAlarms()` و`isIgnoringBatteryOptimizations()`
وتمكين الإشعارات، ويفتح شاشات النظام لمنحها. Capacitor لا يكشف أيّاً من هذه، والمسار الحرج
(§9) يتطلب معرفتها بدقة.

> **تنبيه مهم:** القشرة الأصلية تحمّل التطبيق المستضاف على Vercel داخل WebView (لأن قاعدة
> البيانات على Neon). هذا يعني أن التطبيق **يعمل أونلاين**؛ وضع العمل الكامل دون إنترنت (§12)
> يحتاج محرك SQLite محلي + طابور outbox، وهي مرحلة لاحقة — لا تعتبره مدعوماً الآن.
> عدّل `capacitor.config.ts` (`server.url`) ليشير إلى رابط Vercel الخاص بك قبل التجميع.

### إذن الإشعارات على أندرويد ١٥/١٦ (حرج)

- `POST_NOTIFICATIONS` — يُطلب في الإعداد الأولي بشرح عربي واضح.
- `SCHEDULE_EXACT_ALARM` — مرفوض افتراضياً على أندرويد ١٤+. تحقّق عبر `canScheduleExactAlarms()` ووجّه المستخدم لشاشة النظام بدل السقوط الصامت إلى إنذارات غير دقيقة.
- استثناء تحسين البطارية — وإلا فإن Doze يؤخّر الإنذارات.
- قناة إشعارات عالية الأهمية باسم **«تذكير الجرعات»**.
- إعادة الجدولة عند `BOOT_COMPLETED` و`TIMEZONE_CHANGED` وعند فتح التطبيق.

## البنية

```
src/
├─ core/
│  ├─ db/          schema.ts (Drizzle) · repository.ts · index.ts
│  ├─ engine/      dose · inventory · adherence · cost   ← نقي، بلا React ولا قاعدة بيانات
│  └─ time/        منطقة زمنية، حدود اليوم المحلي، أمان DST
├─ app/            صفحات App Router + Server Actions
├─ components/     مكونات واجهة RTL
├─ server/         تجميع شاشة اليوم
└─ lib/            auth · token · session · utils
```

**قاعدة صارمة:** `src/core/engine/**` و`src/core/time/**` كود نقي ١٠٠٪ — لا يستورد React ولا Drizzle ولا Next. هذا ما يجعل حساب الجرعات قابلاً للاختبار.

### لماذا كل هذا الاهتمام بالمنطقة الزمنية؟

مصر (`Africa/Cairo`) أعادت التوقيت الصيفي سنة ٢٠٢٣. أي حساب يعتمد إزاحة ثابتة (+02:00) **سيفشل**. لذلك:

- كل لحظة تُخزَّن كـ `timestamptz` بـ UTC.
- كل «يوم» هو يوم تقويمي محلي `YYYY-MM-DD` مشتق من المنطقة الزمنية.
- جرعة ٠٨:٠٠ تبقى ٠٨:٠٠ محلياً على جانبي انتقال التوقيت الصيفي.

## الاختبارات

```bash
npm test           # ٦٣ اختباراً على المحرّكات
npm run typecheck
npx tsx scripts/verify.ts   # تحقّق تكاملي مقابل قاعدة بيانات حقيقية
```

الاختبارات تغطي: السنوات الكبيسة، حدود الشهر/السنة، انتقال التوقيت الصيفي، الجرعات المتناقصة، توريث الجداول، وجرعات «عند الحاجة».

أما `scripts/verify.ts` فيتحقق فعلياً من قاعدة بيانات من ضمنها:

- توليد الجرعات **مستقل عن التكرار** (idempotent).
- أخذ الجرعة يخصم المخزون **مرة واحدة**.
- **النقر المزدوج لا يخصم مرتين** — مضمون مرتين: بفحص في التطبيق + فهرس فريد جزئي في قاعدة البيانات.

## ما تم بناؤه / ما بقي

### ✅ جاهز
1. الأساس: Next.js + Tailwind + RTL + عربي + موجّه + مصادقة.
2. نموذج البيانات كاملاً: ١٤ جدولاً + migration.
3. محرّكات الجرعات والمخزون والالتزام والتكلفة (نقية + مُختبرة).
4. شاشة اليوم + تسجيل الجرعات (أخذت / تخطي / تأجيل) مع خصم المخزون ذرياً.
5. إدارة الأدوية والجداول + شاشة المخزون + التقارير.
6. **وضع الوالدة** بشاشة واحدة وزر عملاق، والخروج برقم مرور.
7. بذرة بيانات واقعية: ٩ أدوية قلب ومعدة.
8. **نظام الإشعارات (§9 — المسار الحرج)**:
   - محرّك تنبيهات نقي (اختباره ١٥ اختباراً): عناوين عربية، أزرار إجراء، خريطة UUID→int32 ثابتة، تذكير متابعة بعد فترة السماح، تنبيه معلوماتي للمعتني بلا أزرار، صياغة محايدة (لا «ضاعف الجرعة»).
   - إشعارات محلية مجدولة مسبقاً من الجرعات المولّدة (تنجو من Doze والريستارت عبر مستقبل boot في البلوجن).
   - قناة عالية الأهمية «تذكير الجرعات» مع صوت واهتزاز.
   - **رفض الإنذار الدقيق لا يسقط صامتاً**: إن لم يُمنح `SCHEDULE_EXACT_ALARM` نوجّه المستخدم لشاشة النظام؛ لا تراجع إلى إنذارات غير دقيقة.
9. **مشروع أندرويد الأصلي (Capacitor 8)**: `minSdk 26` / `targetSdk 35`، أذونات أندرويد ١٥/١٦، وبناء **بلوجن Java مخصص** (`AlarmHealthPlugin`) يفحص حالة الإنذار الدقيق وتحسين البطارية وإذن الإشعارات — لأن Capacitor لا يكشفها.
10. واجهات API: `/api/doses/upcoming` (لجدولة الإنذارات)، `/api/doses/action` (إجراء من النقر على الإشعار — نفس ضمان التكرار)، `/api/devices/alarm-health` (إبلاغ وقراءة).
11. **شاشة إنذار حمراء** على لوحة المعتني: إن تعذّر على هاتف الوالدة إطلاق إنذار (إشعارات مغلقة / إنذار دقيق مُلغى / Doze / غياب جدولة >٣٦س) يُخبر المعتني بصوت عالٍ (§1.7 لا فشل صامت).

### ⏭ التالي (حسب خنة البناء)
7. المزامنة وطابور outbox وحل التعارضات (العمل أونلاين أولاً حالياً — انظر تحذير الجوال).
8. الملفات الطبية + تلخيص بالذكاء الاصطناعي (عبر Vercel Function).
9. الأعراض / الطعام / الفحوص الدورية / بطاقة الطوارئ.
10. النسخ الاحتياطي والتصدير والاستعادة.
11. قفل التطبيق + سجل التغييرات + تشديد الأمان.
12. بناء أندرويد فعلي على جهاز حقيقي أندرويد ١٥/١٦ + اختبارات E2E (Playwright).

## الأمان

- لا يوجد أي مفتاح في حزمة العميل. مفاتيح الذكاء الاصطناعي تُستخدم جهة الخادم فقط.
- كوكي الجلسة `httpOnly` + `SameSite=Lax` + `secure` في الإنتاج.
- **رقم المرور** منفصل عن كلمة مرور الحساب وعن قفل التطبيق.
- الفهرس الفريد الجزئي يمنع الخصم المزدوج حتى لو تجاوز التطبيق فحصه.
- `npm audit` نظيف (٠ ثغرات) في وقت التسليم.
